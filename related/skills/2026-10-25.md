## Anthropic：把部分子 Agent 折叠进「单 Agent + Skills」循环，并发布迁移工具包
- 来源：网页/文档　记录者：Skills
- 链接：https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop
- 要点：Anthropic 应用 AI 团队（10-22）称多个企业案例中「单 Agent + Skills 渐进披露」常在质量上优于多子 Agent，成本与延迟更低，Claude Code 系统提示因此缩减 80% 以上。建议逐个把子 Agent 折叠为 Skill + MCP 工具，并用 eval 对比后再决定去留；并行/隔离上下文等场景仍保留子 Agent。
- 摘要：
  - 多个企业案例里，单 Agent 加上 Skills 的质量往往更好，成本和延迟也更低。
  - Claude Code 的系统提示因此缩短了 80% 以上。
  - 子 Agent 应逐个折成 Skill 和 MCP 工具，用同一套 eval 对比后再决定去留。
  - 需要并行或隔离上下文时，仍然保留子 Agent。
- 启示：
  - 拆子 Agent 时逐个折成 Skill 和 MCP 工具，用同一套 eval 变好了再删。
  - 需要并行或隔离上下文的步骤留在子 Agent，不要为了精简一次拆完。
  - 系统提示变长时，优先把做法写进 Skill，而不是继续堆在主提示里。
- 标签：skills,agent-architecture,eval

## anthropics/single-agent-loop-kit：多 Agent 迁移到单循环的评测驱动工具包
- 来源：网页/文档　记录者：Skills
- 链接：https://github.com/anthropics/single-agent-loop-kit
- 要点：配套文章的参考实现（不维护、不接受贡献）：先度量、再合并、再把子 Agent 逐个折叠为技能与工具，每步在同一 eval 上前后对比，数据证明替代可行才删除子 Agent；并建议由小团队维护系统提示与共享 eval，各领域团队负责自己的 skills。
- 标签：skills,eval,build

## MaliciousSkillBench：整合 13 个公开来源的 9,740 技能恶意检测基准
- 来源：网页/文档　记录者：Skills
- 链接：https://arxiv.org/abs/2608.19901
- 要点：7,505 恶意 + 2,235 良性。跨来源（Source-Disjoint）评测下，学习型检测器召回 95.6% 但良性误报 62.4%；Cisco 与 SkillSpector（静态、关 LLM）误报仅 1.1%/0.55%，但召回只有 2.5%/0%。结论：现有检测器尚无「高召回 + 低误报」方案，需同时评估两端。
- 标签：skills,security,benchmark,SkillSpector
